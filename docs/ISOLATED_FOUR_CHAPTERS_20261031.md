## 本轮真实发现并修复的问题

1. **审阅上下文不完整**：简化快照没有心理状态、FactCatalog，审阅者会误判合法旧值和已有 fact_id。审阅改用完整 canonical before-state；明确旧值始终对照章前而非中间操作。
2. **新地点无法提交**：事件里的临时地点未映射 UUID，真实提交事务失败。提交器现在解析该映射，新增回归覆盖。
3. **境界静默丢失**：模型输出 `power_realm`，旧代码接受后忽略。v3 schema 和 Validator/commit 现在拒绝未知字段；Memory 的境界目录改为准确名称，而不是把 rank 拼成 `练气(1)`。
4. **不合法的位置状态**：`前往坊市西头` 等行动描述不能当 canonical 地点。现在要求已有/显式提议地点；编辑补充地点也必须有原文逐字名称、同场景确定性证据。
5. **新配角的境界未落库**：新人物提议可用已知 `attributes.realm`，服务验证并写入其初始状态；不会为不存在境界创造 UUID。
6. **审阅循环过度补录**：明确区分高风险遗漏与可选建议，避免要求每个无名亲属、每次观察都拆成新关系/事实。真正缺失的陶问山、庇护约定仍被指出并补齐。
7. **结构化失败不可定位**：新增脱敏的 `structured_failure_*.json`，保存公开 completion 和具体校验错误，不保存供应商私有思考内容。

## 人工批准与 Agent 干预的边界

没有伪造人类批准。`ReviewApproval.review_kind=automated_test` 只由显式允许测试批准的服务实例接受，正式提交入口拒绝它。

本轮**不是完全无人干预的一键四章成功**。Codex 主 Agent 实际阅读候选和操作，作了精确的局部修订及记忆编辑；具体说明、失败尝试、模型建议、逐字证据重绑定都保留。没有用“全部 correct”覆盖尚未解决的问题，也没有降低证据/依赖检查。

第 4 章静默境界问题在提交后由 SQL 审计发现。因此旧 `isolated_four_20261031_6XeYOj/trial.db` 保留为失败证据；在 `repaired/trial.db` 从正式源库创建新副本，用精确实体键保留 UUID 重放第 1—4 章，仅修正第 4 章境界操作，再从正确状态生成第 5 章。没有原地改写旧 Commit 或 Snapshot，也没有重调用前四章的 Director/ScenePlanner/Writer。

最后一章的局部编辑删除了重复灰雾揭露，改正木牌重复获取，补上夜转天的时间衔接。证据只用 exact text 和确定性偏移重绑定，改变的段落由主 Agent 明确选择新 Catalog ID，未用 embedding/fuzzy matching。
